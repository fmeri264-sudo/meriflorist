# Промокоды

В админке `/admin/bonuses` под бонусными правилами появился раздел «Промокоды».
Администратор может создать, изменить, включить, выключить или удалить код.
Тип скидки: целое число процентов (1–100%) либо фиксированная сумма в рублях.
Коды многоразовые, действуют до отключения, не зависят от регистра букв.

Покупатель вводит код в блоке «Ваш заказ» на `/checkout` и нажимает «Применить».
Скидка относится только к товарам, не к доставке, и не превышает стоимость товаров.
Процентная скидка округляется до целого рубля. Можно выбрать **либо промокод,
либо бонусы**; выбор одного снимает другое. После изменения корзины код нужно
применить заново. Перед созданием заказа код и актуальные цены проверяются сервером.
Сумма заказа, сумма платежа и сумма чека рассчитываются из одних данных.
Заказ хранит снимок кода и скидки: изменение или удаление кода не меняет старые заказы.

## Установка на действующий сервер

Рабочая папка: `/home/helen/project/meriflorist`, процесс PM2: `meriflorist`.
Обновление этого проекта не требует перезапуска `mary-florist`.

1. Сохранить резервную копию рабочей базы средствами Supabase и проверить `git status --short`.
2. Получить ветку `feature/promocodes` из GitHub, проверив отсутствие конфликтующих локальных изменений:

   ```bash
   cd /home/helen/project/meriflorist
   git fetch origin feature/promocodes
   git merge --ff-only origin/feature/promocodes
   npm ci
   ```

3. Применить **только** `migrations/20261030_promocodes.sql` в Supabase SQL Editor.
   Она добавляет таблицу `PromoCode` и поля `Order.promoCode`, `Order.promoDiscount`;
   существующие товары, заказы и бонусные правила сохраняются. Повторное выполнение допускается.
   Если в среде сервера задан действующий `DATABASE_URL` с правами на изменение схемы,
   вместо SQL Editor можно выполнить `node scripts/apply-promocodes.mjs`.
   Скрипт читает `.env.local`, затем `.env`, не выводя значения подключения.
4. В файл окружения сервера (`.env.local` либо уже используемый `.env`) безопасно добавить
   `SUPABASE_SERVICE_ROLE_KEY` — серверный ключ `service_role` **того же проекта Supabase**.
   Он находится в настройках API проекта Supabase. Не использовать префикс `NEXT_PUBLIC_`.
   Ключ нужен только серверным обработчикам; в браузер он не передаётся. Таблица кодов закрыта
   для ролей `anon` и `authenticated`. Уже существующие `SUPABASE_URL`, `SUPABASE_ANON_KEY`
   и `ADMIN_PASSWORD` остаются прежними. Если серверный ключ или таблица не настроены,
   интерфейс покажет ошибку недоступности промокодов; не будет создавать фиктивную скидку.
5. Собрать и проверить перед перезапуском:

   ```bash
   npx prisma generate
   npm test
   npm run build -- --webpack
   pm2 restart meriflorist --update-env
   pm2 save
   ```

   Если PM2 запускается с `MERIFLORIST_BUILD_DIR`, использовать то же значение при сборке.
   В коммите восстановлено повреждённое начало `prisma/schema.prisma`, чтобы клиент
   генерировался после `npm ci`. `prisma generate` генерирует клиент, не меняет базу.
   Реальную схему Supabase обновляет только SQL-миграция из шага 3.
6. Войти в `/admin/bonuses`, создать тестовый код, проверить расчёт на `/checkout`
   и отключить тестовый код. Проверить вариант с процентом, с суммой, неактивным кодом,
   переключение между бонусами и промокодом. Реальную оплату проверять отдельно с тестовым
   терминалом банка либо согласованным заказом.

Новые промокоды не созданы автоматически. Настройки и база рабочего сервера
из облачной среды разработки не изменяются.
